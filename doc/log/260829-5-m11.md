### 検証を受けて直ちに修正したもの(コミット: 本エントリと同群)

1. **操作節のガードの resume**(健全性)— ガードは `resume_ty = Some` の
   環境で推論され、かつ `check_resume_static` は本体しか歩かないため、
   `case ask() if resume(7) > 0 =>` が型検査を通り実行時に落ちた。
   ガードを resume 抜き(`resume_ty = None`)で推論するよう修正。
   interp がガードを resume 無しで評価する事実と一致させた。
2. **同一クラス内の重複メソッド**(健全性)— B4 の検査はクラス「間」しか
   見ておらず、`val f` を 2 回書くと elab は最後で型付け・インスタンス照合は
   最初を見るため実行時に型/アリティ崩壊した。register_effect の dup ops と
   同型の検査を register_class に追加。
3. **--prelude による予約述語インスタンスの迂回**(健全性)— C6 の免除
   条件 `in_prelude` は --prelude のユーザ製プレリュードにも立つため、
   修正前の再現がそのまま復活していた。免除を「組み込み登録であること」
   (`add_instance ~builtin:true`)に変更。
4. **型パラメータ制約経由の予約述語**(健全性)— D38 の 3 経路のうち
   計画 §5 C6 の詳細設計が 2 経路しか塞いでいなかった。`[A: Integral]` が
   型検査を通り実行時に「数値リテラルの型が解決されていません」で落ちた。
   `class_names_of` に予約述語の拒否を追加(let / 署名 / エイリアス /
   extern / クラスメソッド / newtype の全パラメータ経路を被覆)。
5. **newtype パラメータ制約の未検証**(D6 の残り)— register_newtype は
   make_rigids を通らないため未知クラスが素通りだった。パス 1b 後の検証
   ループに DNewtype を追加。
6. **register_instance の検査順**— 予約述語の拒否が未知構成子・カインド
   検査より後ろで、頭の書き方次第で D8 でない理由が先に出た。頭を見た
   直後にも同じ表の検査を置いた。
7. **extern 登録簿の鍵設計の見直し**(H14 の回帰修正 = D23-h の精密化)—
   実装名一本鍵だと `module Fast` と `module Precise` が同じ C シンボル
   `sqrt` を包めない(検証が発見)。**プレリュード保護は実装名
   (`ex_prim`)、二重宣言検査は Keleut 側の修飾名**の 2 鍵に変更。
   `add_extern ~prim name` のシグネチャ変更。
8. **未実装プリミティブのメッセージ**— 表を引いた鍵(ex_prim)と修飾名が
   食い違うとき両方を表示するようにした。
9. **本文の言い過ぎの訂正**(嘘 4 件)— §3.7 / dump.ml「Seq の入れ子を
   作らない」(非末尾の入れ子ブロックは入れ子のまま)、§3.3 の借用例外の
