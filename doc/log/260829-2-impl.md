## 計画からの乖離(裁定の差分)

計画末尾の指示「乖離する裁定をしたときは doc/log の新しいエントリに差分を記録する」に基づく一覧。

1. **明示的 eff 注釈の開放**(§7.6 への追加裁定):
   `@ Print` / `@ {A, B}` のようなラベル付き閉行注釈は、**本体検査では Rigid 尾部・
   公開スキーマでは Generic 尾部**として開く。`@ {}` は閉じたまま(純粋)。
   閉じたままだと sample.kel:357(println を handle の下で呼ぶ)が型付かない。
   Rigid 尾部なので「本体が注釈に無いエフェクトを起こす」ことは引き続き拒否される。
2. **Apply の軽い双方向化**(§7.3 への追加): 関数型を先に分解し、引数(特にラムダ)を
   期待型で検査する。引数ラムダの行が本体の perform 解決(D22)より先に確定するために必須
   (sample.kel:416-418 の with_file + with 糖衣が要求)。
3. **D22 の非修飾解決の絞り込みを「行の最左(=最内ハンドラ)優先」に精密化**。
   計画の「明示ラベルにあるものを優先」だけでは copy(:418)の write が
   File と Console の両方に該当して曖昧になる。最左優先は Scoped Labels の
   最左一致・実行時の最内捕捉と一致する。
4. **組み込み/プレリュードと同名のユーザ宣言は「照合の上で受理」**(§7.4 の運用具体化):
   sample.kel 自身が Unit / List / Console / Add / Add[Int32] / Never 等の
   プレリュード相当を宣言するため。実体は組み込み側を使い、ユーザ vs ユーザの重複は
   従来どおりコヒーレンス違反で拒否する。
5. **module 平坦化(D21)を M10 から M9 に前倒し**: module Parser を参照する parens が
   sample.kel §9 の途中にあり、M9 の完了条件(§9-§10 の型検査)がこれを要求した。
   実装は改名 + 同義語表(非修飾名 → 修飾名)。コンパニオン型規則(:581)も同じ表で通る。
   **未対応**: module 内 let の相互参照(sample.kel は使っていない)、module の入れ子、
   非コンパニオン内部型の同義語が外にも見えること、pub の可視性検査(§2.1 どおり延期)。
6. **テスト機構は cram 一本**(§9.1-9.2 の (rule (diff)) + run_tests.ml を置き換え):
   dune promote の運用は同じで追加コードがゼロ。`.t` ファイルへの追記だけでケースが増える。
7. **パターン束縛の match 脱糖はパーサでなく elab 側**(§6.4 の1行の変更):
   トップレベルの `let (a, b) = ...` は式に脱糖できないため、elab が単一ケース match と
   同じ扱い(単相束縛 + 網羅性キュー)で両方の位置を一本化した。
8. **resume は値(VResume)ではなく env 経由**(§8.2 の変更): second-class(D19)を
   実装レベルでも強制する。値表現に VResume は存在しない。
9. **空の match 本体を文法で許可**: `n match {}`(Never の節ゼロ網羅)。あわせて
   Maranget の complete 判定を「シグネチャが Some [] なら roots が空でも網羅」に修正
   (MiniLang:1727 の roots.nonEmpty 条件は Never の節ゼロで誤って非網羅になる)。
10. **menhir --strict の投入は M2 でなく M3 開始時**(§3.2 の1マイルストーンずれ):
    M2 時点では文法が無く、未使用トークン警告がエラー化するため。
11. **数値パターンの重複検出は値正規化**(0x1 と 1 を同一視)。計画に記述が無かった点の裁定。
12. **クラスメソッド名の値環境登録は非修飾+修飾の両方**。メソッド参照 `map` / `Functor.map`
    の両方が引ける(§7.4 の「両方」を環境レベルで実装)。
