# 260829-3: 文芸化(literate プログラミング化)の規約と記録

- 日付: 2026-08-29
- 対象: 全ソース(lib/*.ml, lib/parser.mly, lib/prelude.kel, bin/main.ml)を
  `../reference/MiniLang.scala` と同じ文芸的プログラミングの流儀に書き換えた。
  **コードは 1 トークンも変更していない**(検証方法は後述)。
- 読む順序と章立ては README の「教材として読む」を参照。
  実装全体の見取り図は第1章 (lib/syntax.ml) の冒頭。

## 規約

- 記事本文 = **列 0 から始まる**ブロックコメント。開始は `(* `、継続行は空白 3 個の
  インデント、最終行の行末に ` *)`。中身は Markdown(見出し `# / ## / ###`、表、
  引用、箇条書き)。`.kel` は `// ` 行コメント = 本文(MiniLang.scala と同じ)。
- 関数内部の説明はコードのインデントに合わせた通常のコメント(記事変換では
  コード側に残る)。
- 禁止事項(OCaml はコメント内でも文字列を字句解析するため、破るとビルドが壊れる):
  - コメント内の `"`(引用は 「」 か `` ` ``)
  - 単独の `*)` や対にならない `(*`(対になったコード例は可)
  - `{|`
  - prelude.kel 内の `|prelude}` の並び(OCaml への埋め込み区切り)
- ライセンスヘッダは各ファイル先頭に 2 行形式
  (`(* Copyright …` + 3 スペース継続の SPDX 行)。weave は記事から除外する。
- 記事変換: `awk -f tools/weave.awk lib/unify.ml > unify.md`
- 節参照の記法: 本書の章節は「§N.M」(必要なら「第N章 (ファイル名) の §N.M」)。
  計画 doc/log/260829-1-plan.md は「計画 §N.M」、仕様は「sample.kel §N」、
  お手本は「MiniLang §N」。データ構築子は「コンストラクタ」、型は「型構成子」。
- **ocamlformat / `dune fmt` を掛けないこと**。列 0 ブロックが再インデントされ、
  規約(と weave)が壊れる。

## コード不変の検証方法

1. コメント除去+空白正規化したコード部を、書き換え前(2d00063)と比較して
   全 19 ファイル完全一致(文字列・quoted string・文字リテラル対応のストリッパで機械検査)
2. `dune build` / `dune runtest` 緑(cram ゴールデン不変 = 観測可能な挙動不変)

## 手順の記録

1. 執筆: 章グループごとに 10 エージェント並列。スタイルガイド(文体・章立て・
   禁止事項・用語)を共有して書き分けた。
2. 敵対的検証: 章ごとの事実検証 10 + 章間整合検査 1 の 11 レンズ。本文の事実主張を
   コード・仕様・実測(ビルド済みバイナリに .kel を食わせる)と突き合わせ、
   **77 件の指摘**(wrong 17 / misleading 25 / minor 35)。
3. 修正: 章グループごとに 10 エージェント並列で 77 件全部を適用(見送り 0)。
   各修正は指摘の evidence を再確認してから適用した。

検証で落ちた主な誤り(教材として害になるもの): 操作なしエフェクトの宣言構文が
「無い」という主張(実際は書ける)、`1u8` が NotImplemented 側だという分類
(実際は型エラー)、「末尾カンマは全リストで許す」(ty_args / typaram_list /
lowline_list は不可)、EQ_GREATER の pop 条件の過大な説明、浮動小数の重複判定
「正しい」という主張(%.12g 正規化は相異なるリテラルを潰し得る)、など。

## 文芸化で見つかったコード側の課題(未修正)

文芸化はコメントのみの変更と決めたため、執筆・検証中に見つかった以下は未修正。
本文には正直に書いてある。直すときはこの一覧から。

挙動に関わるもの:

1. builtin.ml `f64_cmp` が多相 compare のため NaN の順序が IEEE と異なる
   (`__float64_lt(nan, 1.0)` が真になる。等価だけは `=` で NaN <> NaN を守っている)
   — **260829-4 M12(A1)で修正済み**(NaN ガード、D23)
2. value.ml `show` の VFloat64 が `string_of_float`(%.12g)のまま。実行時
   エラーメッセージ内の Float64 表示だけ 0.1+0.2 が 0.3 に丸まる
   (Show[Float64] は float_repr に修正済み)
   — **260829-4 M12(A2)で修正済み**(float_repr を第12章へ移設し共用、D27)
3. interp.ml 末尾 resume 最適化の経路は、`resume(f())` の引数評価が例外で
   脱出すると discontinue が走らず、捨てた継続内の cancel が動かない
   — **260829-4 M13(B1)で修正済み**(引数評価だけを包み、continue は
   値の枝のまま。性能は不変)
4. exhaust.ml の数値パターン重複判定: 浮動小数の正規化が `string_of_float`
   (%.12g)なので、有効数字 13 桁目以降だけが違うリテラルを重複と誤判定し得る
   — **260829-4 M12(A3 / A10)で修正済み**(±0 畳み + %.17g の単射鍵、
   整数も Int64 全域に。D24)
5. decls.ml `add_data`: プレリュード所有名を**異なるコンストラクタ集合**で
   再宣言しても黙って無視される(sample.kel は同じ定義を書くので実害未発生)
6. interp.ml `register_class_methods`: 同名メソッドを持つクラスが複数あると
   非修飾名の解決が登録順に依存する(修飾名は常に正しい)
   — **260829-4 M11(B4)で修正済み**。実際は「登録順依存」に留まらず、
   elab(宣言順)と interp(ハッシュ順)が別のインスタンスを選ぶ
   コヒーレンス破れだった。同名メソッドの重複宣言を elab が拒否する
7. parser.mly `block_of_items`: 3 文以上のブロックの `Seq` に末尾から 2 番目の
   文の位置が付く(位置つきエラー未接続のため実害はまだ無い)
   — **260829-4 M11(E2)で修正済み**。実際は「実害はまだ無い」が誤りで、
   借りていたのは位置でなく ElabData ノードそのもの。型の付くプログラムが
   実行時に落ちる実害があった(詳細は 260829-4 §7 E2)
8. lexer.ml `parse_number` の幅 9999 センチネルが、エラーメッセージに元の桁数
   ではなく `1i9999` を出す
   — **260829-4 M12(A5)で修正済み**(接尾辞原文 n_suffix_text を保持、
   センチネルは書けない -1 に)
9. driver.ml の警告判定が表示文字列の先頭バイト覗き見(`'\xe2'`)

負債・未使用(消すか使うかを決める):

10. dump.ml が `Prims.show_bin_op` と同じ演算子表を二重に持つ(show_bin_op は未使用)
11. 未使用: `Syntax.EmptyData` / `Tree.data` / `Tree.loc_of` / `Tree.oid_of` /
    `Decls.method_scheme` / `Type.label_to_oid` / `Type.oid_to_label`。
    `Driver.type_check_string` / `eval_string` は API として意図的に残置
12. exhaust.ml `missing` / `useful` の `roots <> []` 条件は証明可能に冗長。
    キューの末尾追加(`!pending @ [entry]`)は二乗
13. builtin.ml `find_prim` が線形探索で、組み込みクラスメソッド呼び出しの
    たびに走る(静的インスタンス焼き込み(計画 §8.5)が本筋)
14. aux.ml `NotImplemented` の実質的な用途が「到達しないはずの防御的な枝」
    1 か所だけになっている(`1u8` も module の入れ子も実際は型エラー側)
