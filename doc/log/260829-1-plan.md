## 4. AST・型表現(`lib/syntax.ml` 全面改訂)

### 4.1 内部型 `Type.ty`

```ocaml
module Type = struct
  type level = int

  (* 名前インターン。既存 label_to_oid(syntax.ml:28-41)を「名前一般」に格上げ。
     record ラベル / エフェクト名 / 型構成子 / クラス名 / ctor 名 / 識別子で共有。
     名前空間の区別は使う側の文脈(表)が担う *)
  val intern : string -> oid          (* 旧 label_to_oid をエイリアスとして残す *)
  val name_of : oid -> string

  type kind =
    | KStar
    | KRow                            (* record / variant / effect 行で共通。分けない *)
    | KArrow of kind * kind           (* F[_] *)
    | KVar of kind_ref                (* D7。宣言終了時 KStar に既定化 *)
  and kind_ref = { k_id : oid; mutable k_link : kind option }

  type cls = oid list                 (* 1パラメータクラスの制約集合(Integral/Fractional 含む) *)

  type var_info = { vid : oid; vlevel : level; vkind : kind; vcls : cls }

  type ty =
    | TCon of oid * ty list           (* 名目/組込み構成子の飽和形 *)
    | TApp of ty * ty                 (* HKT。頭が型変数のときだけ現れる(repr が保証) *)
    | TArrow of ty * ty * ty          (* 引数(_item 行の TRecord) * 返り値 * エフェクト行 *)
    | TRecord of ty
    | TVariant of ty                  (* 構造的ヴァリアント。行1個 *)
    | TRowEmpty
    | TRowExtend of oid * ty * ty     (* label * field(エフェクトならラベル引数) * rest *)
    | TVar of tvar ref
  and tvar =
    | Unbound of var_info
    | Link of ty
    | Generic of var_info
    | Rigid of var_info
end
```

- 旧構成子の移行: `TLongId` → `TCon(id, [])`、`TApply` → `TCon`/`TApp`(`tapp` が振り分け)、
  `TTuple` → 廃止(D4)、`TVariant(params, name, ctors)` → `TCon` + 宣言表(型に宣言を埋め込むと
  再帰型で generalize/instantiate が無限走査になるため)、`TGiven` → 廃止(制約は `vcls` へ)
- `repr`: Link 連鎖の経路圧縮 + `TApp` の再正規化(MiniLang:221-236 の直訳、約10行)。
  **以降の全関数は「まず repr してから match」を鉄則にする**
- 補助: `tapp` / `app_spine` / `row_fields` / `row_tail_var` / `row_append` /
  `new_var ~kind ~classes level` / `new_row_var` / `new_rigid` / kind の
  `kind_repr`/`new_kind_var`/`k_arrow`/`drop_arrows`/`same_kind`(bool 返し)/`default_kind`/`show_kind`
- 組み込み型名(v0): `Boolean` `Int32` `Int64` `Float64` `String` `Never`。
  他の数値幅(Int8/16, UInt 系, Float32)の**名前と接尾辞は受理するが elab で v0 未対応エラー**(D13)。
  **`Unit` は名目型ではなく `TRecord TRowEmpty`**(sample.kel:41,112)。プレリュードの型エイリアスとしてのみ名前を持つ
- 予約クラス oid: `Integral` / `Fractional`(D8)。**組み込みの操作なしエフェクトラベル: `Heap` / `Blocking`**
  (どちらも宣言構文が無いので decls.ml が直接登録する)

### 4.2 表層 AST(Data functor は維持)

```ocaml
module type Data = sig
  type t
```

```ocaml
  lb_tparams : type_param list;     (* let f[A, E] / let empty[A]: ... の [A, E]。値束縛にも付けられる *)
  lb_params : pat list option;      (* None = 値束縛。Some ps = 関数定義(パーサは Lambda を作らずここに保持) *)
  lb_ret : type_exp option;         (* : T *)
  lb_eff : type_exp option;         (* @ E *)

}
and let_binding = Data.t * let_binding'
```

**注釈の置き場所の裁定**: 式レベルの `Annot` ノードは持たない。`let b: Int64 = 0` の注釈も
関数の返り値・エフェクト注釈も、すべて `let_binding` のフィールドに置く(skolem 化検査は
let_binding 単位で走る。§7.3)。パラメータの注釈だけは `PAnnot`(パターン側)。

パターン(既存 syntax.ml:187-202 からの差分):

### 5.1 トークンの増減(現 parser.mly:20-100 の 81 個 → 64 個)

  COLON_EQ PLUS_EQ HYPHEN_EQ COLON_PLUS COLON_HYPHEN COLON_PLUS_COLON COLON_HYPHEN_COLON PLUS_COLON
  HYPHEN_COLON HYPHEN_GREATER ELSE THEN END EXCEPTION RAISE GIVEN INTERFACE WHERE OF GRAVE_ACCENT
  LAZY TILDE NUMBERSIGN SINGLE_QUOTE VERTICAL_GREATER WHEN LCBRACKET RCBRACKET` と `$` 引用識別子(lexer.ml:212-226)
- `return` / `cancel` / `structural` / `Type` / `EffectRow` は**キーワードにしない**(文脈で普通の識別子として受ける)
- **識別子の字句規則を明文化**: `('a'..'z' | '_')` 始まりで**長さ2以上**、または `'a'..'z'` 単独を
  `LOWER_IDENTIFIER`(`_item` `_0` `__int32_add` `yield_` を含む)。**単独の `_` だけを `LOWLINE`** にする
  (既存バグ 0.2-13 の修正。`case _ =>` `[F[_]]` `List[_]` が `LOWLINE` に依存する)
- **トークンの位置ペイロードを廃止**(D16)。`%token <Location.t> LET` → `%token LET`。
  位置は字句層のバッファが `{ tok; sp; ep }` の三つ組で運び、Menhir の `$sloc` に正しく流れる(0.2-9 の修正)

### 5.2 コメント・shebang(新規)

- `//` 行コメント: 改行は消費しない(ASI のため NL を残す)
- `/* */` 入れ子ブロックコメント: depth カウント。**中に改行を含んでいたら NL 1個として振る舞う**
  (コメントを足しただけで行結合が変わるのを防ぐ)。EOF 到達は「unterminated block comment」エラー
- `#!` shebang: オフセット0のときだけ行末までスキップ。それ以外の `#!` は字句エラー
- catch-all `| _ -> EOF`(lexer.ml:263)を廃止し、`eof` と `any → 字句エラー` に分ける
- `read_newline` に `'\r'` を追加(CRLF 対策)

### 5.3 `{` の読み分け(D12)

sample.kel:20-26 の規則(t1 = `{` の次、t2 = その次。先読みは NL をスキップして行う):

| t1 | t2 | 種別 |
|---|---|---|
| `}` | — | `LBRACE_RECORD`(空 = Unit。専用トークンは作らない) |
| `extends` | — | `LBRACE_RECORD`(`{extends R}`) |
| IDENT | `:` | `LBRACE_TYPE` |
| IDENT | `=` / `,` / `with` / `extends` | `LBRACE_RECORD` |
| それ以外(IDENT `}` を含む) | | `LBRACE_BLOCK`(`{x}` はブロック。パンニングは `{x = x}`) |

実装: `read_raw_token`(生)と `read_token`(ASI)の**間に独立した再分類層**を挟む。
先読みで覗いたトークンはキューに残り、自分の番が来たとき個別に再分類される(入れ子も自然に処理)。
spike の `260829-1-spike/menhir/lex.ml` がこの層の参照実装。

文法側: **式位置だけが RECORD と BLOCK を区別する**。次の位置には対立候補が無いので
`%inline lbrace: LBRACE_BLOCK | LBRACE_RECORD | LBRACE_TYPE` の union 非終端で受ける:
**型位置・パターン位置・instance 本体・クラス本体・module 本体・effect 宣言本体・`run` の本体**。
match/handle 本体は必ず `case` で始まるので BLOCK 固定でよい。
(パターン位置を union にしないと `let {x} = p` — IDENT `}` で BLOCK — が書けなくなる。
`run h {}` — `{}` は RECORD — も union が要る。)

**2トークン先読みの帰結(言語仕様側の制限として §12 に記録)**:
- 単一フィールドのレコード式/パターンは `{x = x}` と書く(`{x}` はブロック。sample.kel:26 の裁定そのもの)
- **`{base with ...}` の base は小文字識別子1個に限る**。`{p.x with ...}` `{f(a) with ...}` は
  t2 が `.`/`(` なので BLOCK に分類される(文法側で base を `exp` にしても字句側で既に決まっている。
  sample.kel の用例はすべて単一識別子)

sample.kel の全 `{`(約78箇所)を上表で照合済みで誤分類ゼロ(検証で独立に再確認済み)。

### 5.4 ASI の改定

既存機構(lexer.ml:265-313)の骨格を使うが、次の4点を変える:

1. **述語の中身の当てはめを入れ替えたうえで**(既存バグ 0.2-12)、集合を Keleut 用に差し替える:
   - `can_end_statement`(NL の**前**に来てよい = 文終端): `RPAREN RBRACKET RBRACE` 識別子 `HASH_IDENT` リテラル `HOLE`
   - `can_begin_statement`(NL の**後**で文を開始できる): 宣言キーワード(`LET TYPE NEWTYPE EFFECT MODULE PUB EXTERN`)、
     **`VAL DERIVE`**(クラス本体の行頭。無いと sample.kel:300-303 の `derive structural` の前で NL が落ちて
     パースエラーになることを実測済み)、`WITH PERFORM RESUME RUN FN`、識別子・リテラル・`HOLE EXCLAMATION`、
     `LBRACE_*`、**`LPAREN`**(← sample.kel:220「行頭の `(` は前の行の継続とみなさない」の実装)
   - **意図的に除外**(= 行継続): `AND`(`let rec ... and` が繋がる。最重要)、`CASE`、
     `MATCH`/`HANDLE`(後置)、`DOT`/`BACKSLASH`(チェーン折り返し)、`EXTENDS`、`VERTICAL`
     (`type A = #X | #Y` の折り返し)、二項演算子群、閉じ括弧、`EQ EQ_GREATER COLON COMMA AT LBRACKET IF LOWLINE`
2. region 遷移(lexer.ml:276-293): **`LBRACE_BLOCK` → 文区切り region(旧 InCbracket)、
   `LBRACE_RECORD`/`LBRACE_TYPE` → NL 抑止 region(InParen 相当)**、`RBRACE` で pop。
   レコード・型・エフェクト行の中では NL は決して文区切りではないので、これにより
   `{r ⏎ with l = e}` のような折り返しも自然に通る(旧計画で「既知のトレードオフ」としていた
   `WITH` の問題はこの分割で消える)
3. `InPatternClause` の pop を `HYPHEN_GREATER` → **`EQ_GREATER`** に(既存バグ 0.2-14 の修正)。
   既知の制限: ガード内に `fn(x) => ...` があると内側の `=>` で先に pop する(sample.kel に該当例なし。
   踏んだら「深さ0の `=>` のみ pop」に直す)
4. 生トークン供給を再分類層(§5.3)経由に

`;` は文の区切りとして**どこでも**書いてよい(トップレベルの単独 `;` 行(sample.kel:218)も、
ブロック内の `{ println(u.id); u.name }`(:335)も)。文法側の `items` が余分な `;`/`NL` を
読み飛ばす形にする(ASI の誤挿入への保険にもなる。必須)。

ASI の全規則は spike の手書きレキサで sample.kel 全文に適用し、誤挿入・欠落ゼロを確認済み。

### 5.5 数値リテラル(D13)

```ocaml
type num_suffix = NsInt of int | NsUInt of int | NsFloat of int   (* i64 / u8 / f32 *)
type number = { n_text : string; n_is_float : bool; n_suffix : num_suffix option }
```

- 字句規則: `0x`/`0o`/`0b` + 数字列、10進(小数点・指数 `e`/`E` 対応)、桁区切り `_` 許可、
  末尾に `i`/`u`/`f` + ビット幅。旧「`0` + 8進数字」は**廃止**(`010` = 8 の罠を持ち込まない。`0o` に統一)
- `read_number`(lexer.ml:115-143)は破棄し、`lexeme` を受け取る純関数 `parse_number : string -> number` に置換
- **符号**: 字句は常に `HYPHEN` を独立トークンにし、**parser の prefix 規則で `HYPHEN NUMBER` を
  負リテラル(`n_text` の先頭に `-` を付与)に畳む**。`1-2` の分割事故を防ぎつつ、AST 上は
  「単項マイナス演算子が存在しない」= sample.kel:72 の意味論を満たす
  (sample.kel:260 が `is_even(0 - n)` と書いているのがこの読みの裏付け)。パターンの負リテラルも同様。
  `add_exp` の二項 `-` と併存して conflict なし(実測)
- 評価時は elab の解決型(defaulting 済み)を見て `Int32.of_string` / `Int64.of_string` /
  `float_of_string`(§8.3)。範囲外は実行時エラーに包む。
  将来符号なしを実装するときの注意(実測済み): **10進の符号なし最大値は `of_string` が受けない**ので
  `"0u"` を前置してから呼ぶこと(`Int64.of_string "0u18446744073709551615"` は通る)

### 5.6 文字列

## 6. 構文解析(`lib/parser.mly`)

`%parameter <Data : Syntax.Data>` と `Tree = Syntax.Make(Data)` は維持。`new_tree` を `mk $sloc` に変更。
**文法の骨格は spike の `260829-1-spike/menhir/kel.mly`(`--strict` で conflict 0、sample.kel 全文パース済み)を
出発点にする。** 以下の設計判断はすべて spike に織り込み済み(`[FIX-n]` コメント参照)。

### 6.1 全体構造

- トップレベル・module 本体・ブロック・instance 本体を**同じ非終端 `items`** で受け、
  文脈違反(ブロック内 `module` 等)は elab が検査する。クラス本体(`val` / `derive`)と
  effect 宣言本体(`op: ty` の並び)だけは専用非終端
- `items` は余分な `semi`(NL/SEMI) を読み飛ばす。`let rec ... and` の間に `semi?` を**書かない**
  (書くと shift/reduce。NL は ASI 層が捨てるので `LET REC binding (AND binding)*` と素直に書けば足りる。実測)
- **match 節と handle 節は同一の `clause` 非終端**(`case pat (if exp)? => exp`)。
  `return`/`cancel`/操作名(`Print.print` 修飾含む)は `PCtor` の頭として受かり、分類は elab(§7.3)
- **カンマ区切りの全リスト(引数・パラメータ・タプル・型引数・ブレース型の要素・ctor フィールド)で
  末尾カンマを許す**(sample.kel:397 の effect 本体、:512-515 のパラメータリストに実例。
  `sep_list1(X): X | X COMMA | X COMMA sep_list1(X)` の形なら `(a)` と `(a,)` を action で区別でき conflict なし。実測)
- **ドット連鎖は式では `long_id` 非終端を使わない**。`postfix_exp DOT lower_id | postfix_exp DOT upper_id` の
  一様な左再帰チェーンで食い、「先頭の連続する大文字成分 + 直後の1成分をパスに畳み、残りをレコード選択にする」のは
  **意味アクションの仕事**にする(`long_id` 併置は `Foo.bar` で shift/reduce になることを実測済み。
  型位置・パターン位置には競合する DOT 規則が無いので `long_id` をそのまま使ってよい)。
  `Construct` と `Apply` の分岐は「**パスの最後の成分が大文字なら Construct、小文字なら Apply**」
  (`Parser.bind(...)` は Apply、`Parser.Parser(...)` は Construct)。
  `t._0` の `_0` は LOWER_IDENTIFIER なので選択規則にそのまま乗り、`t.0` は構文エラー(sample.kel:120 の意図どおり)

### 6.2 式の優先順位(弱→強)

```
exp          := FN params => exp | postfixed
postfixed    := postfixed MATCH clause_body | postfixed HANDLE clause_body | or_exp
or_exp       := or_exp || and_exp | and_exp
and_exp      := and_exp && cmp_exp | cmp_exp
cmp_exp      := add_exp (== != < <= > >=) add_exp | add_exp     -- 比較は非結合
add_exp      := add_exp (+ -) mul_exp | mul_exp
mul_exp      := mul_exp (* /) prefix_exp | prefix_exp
prefix_exp   := ! prefix_exp | - NUMBER | postfix_exp
postfix_exp  := postfix_exp . ident | postfix_exp \ lower_id
              | postfix_exp ( args )                            -- 呼び出し(並置適用は無い)
              | atom
atom         := リテラル | ??? | lower_id | upper_id | #Ident
              | perform dotted_op(args) | resume(exp?) | run h lbrace items }
              | LBRACE_BLOCK items } | record_exp | paren_exp
```

- 後置 `match`/`handle` は最弱なので **`x match {...} + 1` は書けない**(`(x match {...}) + 1` と括弧が要る。
  Scala と同じ。§12 に記録)
- `#Foo(a, b)` は atom に引数を持たせず、**postfix の呼び出し規則で受けて意味アクションで `Variant` に畳む**
  (atom 側に `(args)?` を置くと shift/reduce。実測)
- `resume` は `RESUME LPAREN exp? RPAREN` の専用規則。**引数を `record_of_args` に通さない**
  (`resume(e)` のペイロードは操作の返り値そのもの。`{_item = e}` に包むと op_ret と単一化できない)
- `(` の読み分けは文法側で吸収: 式位置はカンマの有無(`(a,)` は末尾カンマ)。並置適用が無いので呼び出しの `(` に曖昧性は無い
- レコード式: `{}` / `{l = e, ...}` / パンニング `{a, b}` / `{base with fields}`(base は lower_id、§5.3) /
  `{fields extends e}` / `{extends R}`
- `let` 束縛の被束縛パターンは節のパターンと**共有しない**。専用の `bind_pat`
  (`_` / 変数 / **大文字頭** ctor / レコード / タプル / 括弧)を使う — 節側は `case print(m)` のため
  PCtor の頭に小文字を許すので、共有すると `let f(x) = e` が「関数定義」と「小文字 ctor パターン」で
  reduce/reduce になる(実測。r/r は記述順で黙って倒れるので特に危険)

### 6.3 型式

```
ty        := union_ty eff_opt | arrow_ty
arrow_ty  := ( ty_list0 ) => arrow_ret
arrow_ret := union_ty eff_opt | arrow_ty        -- 入れ子 arrow の外側には @ を書けない(要括弧)
union_ty  := app_ty (| app_ty)*
app_ty    := long_id ty_args? | LOWLINE | #Ident ty_payload? | brace_ty | ( ty_list )
brace_ty  := lbrace brace_elem,* (extends ty)? }   -- レコード型・エフェクト行・行 splice を1本で
eff_opt   := (@ eff)?     eff := long_id | brace_ty
```

- **`paren_ty` を単一規則にせず arrow を分離する**(単一規則は `(A)=>B|C` / `((A)=>B)[C]` /
  入れ子 arrow の `@` で3種の conflict を生むことを実測済み)。裁定:
  **`@` は直前(最内)の矢印に結合**し、曖昧な位置は括弧を要求(sample.kel の全用例は括弧済み)。
  **型位置の `(A)` はグループ化ではなく常に 1-タプル `{_item: A}`**(§12 に記録)
- `brace_ty` の要素は `l: T`(フィールド)か `Name[args]`(エフェクトラベル / splice される行エイリアス)。
  意味の判別は elab。これにより `@ {}` / `@ {Print extends E}` / `{ReqId, Logger, Tracer}`(sample.kel:446)/
  effect 宣言本体が全部同じ規則に乗る(record 型と eff 行を別非終端にすると r/r になることを実測済み)
- `#Syntax((Int32,Int32))` と `#Syntax(Int32,Int32)` の両方を受け、後者は畳む(式・パターンと同じ規則)
- カインド注釈は `COLON upper_id`(`Type` / `EffectRow` は識別子のまま受けて elab が解釈)
- 型パラメータ束縛子: `upper_id` / `lower_id`(リージョン変数 h)/ `upper_id [ _,* ]`(`F[_]` — その場で KArrow 確定)

### 6.4 パーサで行う脱糖(一覧)

| 表面構文 | 脱糖後 |
|---|---|
| `(a, b, c)` | `RecordExtend` の入れ子(`_item`、`fold_right` で先頭が最外) — 評価順 a→b→c が自動で出る |
| `(a)`(式) | **グループ化。`a` そのもの**(タプルにしない) |
| `f(a)`(呼び出し) | `{_item = a}`(1要素の引数行) |
| `#Foo(a)` | **ペイロード `a` そのもの**(1要素タプルにしない。`#Syntax((l,c))` と `case #Syntax(l, c)` の単一化がこれに依存) |
| `#Foo(a, b)` / `#Even` | `#Foo((a, b))` / `#Even(())`(式・パターン・型共) |
| `(A, B)`(型) | `{_item: A, _item: B}`(閉じた行) |
| 引数リスト / パラメータリスト | `_item` レコード(D5)。ヘルパ `record_of_args`(ラベル付き引数は `l = e` でラベル指定) |
| `t._0` / `t._N` | `t._item` / `(t \ _item)ᴺ._item` |
| `{a, b}` パンニング | `{a = a, b = b}`(式・パターン共) |
| `with pat = e` ⏎ 残りの文 | `e` は `Apply(f, args)` であることを要求し(でなければ「with の右辺は呼び出し」エラー)、**引数行の最内 `RecordEmpty` を `RecordExtend(RecordEmpty, _item, k)` に差し替える**(5行の再帰。評価順から継続が最後に評価されるのも自動で正しい)。継続 `k` は **pat が `_` なら `fn() => 残り`(0引数)、それ以外なら `fn(pat) => 残り`(1引数)**。`with _ = with_file(src)`(sample.kel:416-417)の `body: () => A` と、`with x = Parser.bind(..)`(:430)の `(A) => ...` の両方がこれで整合する |
| `newtype UserId(Int32)` | `newtype UserId = UserId(Int32)` |
| `let {x, y} = p`(パターン束縛) | 単一ケース match(網羅性警告に乗せる) |
| `-` NUMBER | 負リテラル(§5.5) |

AST に残すもの(脱糖しない): `BinOp`(D9)、`{r with l = e}`(`RecordUpdate`)、`Handle` の節分類、
`Construct` のラベル指定引数(並べ替えは elab が行い `resolved` に書く)。

### 6.5 作業ステップ(M2〜M3 内)

S2-1 トークン総入れ替え + 式のみの最小文法(`%start single_exp`) → S2-2 ブレース再分類層 + ASI +
ブロック/match/handle → S2-3 型式とパターン → S2-4 宣言一式 → S2-5 sample.kel 全文パース。
各段階で `--dump-tokens` / `--dump-ast` のゴールデンを固定する。spike の kel.mly / lex.ml を下敷きにし、
`--strict` を最初から入れる(§3.2)。

## 7. 型推論(`lib/elab.ml` の全面改訂)

### 7.1 ファイル分割

### 7.2 推論の骨格

- シグネチャ: `elab_exp : env -> level -> ty (* eff *) -> exp -> ty`。
  **eff を下向きに渡す**(MiniLang §11 の形)。level は従来どおり引数(グローバル化しない)
- 環境: `{ values : ty IdMap.t; types : type_binding IdMap.t; resume_ty : ty option }` の不変 Map(D10)。
  `resume_ty` はハンドラ操作節の中でのみ Some(`Resume` の型付けと「節の外の resume」検査に使う。
  **return 節・cancel 節では None に戻す** — `retc`/`exnc` に継続は存在しない)
- `generalize` は**in-place**(tvar を書き換える。戻り値 unit)に変更。
  AST ノードに `set_ty` 済みの型と共有が切れない。Rigid は決して一般化しない。
  述語つき変数はここで既定値に bind(D8)
- `instantiate`/`skolemize`/`subst_params` は共通の `map_generics`(memo つき)に一般化。
  `instantiate` が `vkind`/`vcls` を**複製する**ことが型クラスの複製点(既存実装はここが抜けている)
- `bind` にカインド一致検査(`same_kind`)と `vcls` の伝播(`add_class`)を追加。
  `occurs_adjust` に **Rigid ケース(レベルが深ければ脱出エラー、下げない)** を追加
- **`rewrite_row` は挿入するフィールドを必ず新変数 + `bind` 経由で単一化する**(MiniLang:794-842 の形)。
  既存の「フィールド型を直接 splice する」実装は過剰一般化を起こす(既存バグ 0.2-11)ので流用しない
- `unify` に `TArrow` の3要素、`TApp` の3ケース(v1 で実働、骨格は v0)、`TGiven` ハックの削除に加え、
  **`(TVar _, _) | (_, TVar _)` の Rigid ケースを専用エラー**にする(「スコープ付きの型が一致しません」。
  MiniLang §16-7 の `runST { let r = newref 0 in runST { deref r } }` は occurs_adjust ではなく
  **この経路**(行の中の Rigid 同士の不一致)で落ちる — 検証で確認済み)
- 掃き出しの順序: **網羅性検査の遅延キューは各 let 束縛群の generalize の直前に drain する**
  (generalize の後に `close_variant_rows` が走ると Generic 化済みの行変数に unify を掛けて内部エラーになる)。
  宣言終了時に走らせるのは `default_numerics()` → `check_ambiguity`(v1)のみ
- **宣言は2パス**: 1パス目で type/newtype/class/instance/effect の頭部と、
  **注釈が完全なトップレベル let の署名**を登録(sample.kel:334-335 の `user_names` が後方の `println`(:347) を
  参照する前方参照はこれで通る。注釈が不完全な let は宣言順依存のまま — §12 に記録)。
  2パス目で本体を推論

### 7.3 主要規則(MiniLang との対応と Keleut 差分)

| 式 | 規則 |
|---|---|
| リテラル | 接尾辞あり → 具体型(v0 対応外の幅はエラー)。なし → `Integral`/`Fractional` 述語つき新変数(パターン側 `PNumber` も同じ) |
| `Ident` | `instantiate`(MiniLang:1300-1303) |
| `Lambda` | 本体に**新しい行変数**を割り当てる。返す型は `TArrow(引数行, body_ty, body_eff)` |
| `Apply` | `unify tf (TArrow (args_row, ret, eff))` — 関数の行を**呼び出し側の eff** と単一化(MiniLang:1319-1324) |
| `Let`/`LetRec` | 値制限(`is_value`。ブロック(`Seq`/`Let` 連鎖)は保守的に非値)。`let rec` は単相で束縛→本体推論→unify→generalize(0.2-5 修正)。多相再帰不可 |
| 注釈付き let_binding(`let f[A, R](p: T): U @ E = body`) | (1) level+1 で型パラメータを **Rigid** として束縛(`[A: Add + Mul]` は vcls へ、`F[_]` は KArrow)、(2) 注釈を elaborate、(3) 本体を注釈の eff で推論して unify、(4) 環境登録用に注釈を **Generic** で elaborate し直す(2回 elaborate が最短)。MiniLang:1383-1394 と同じ仕掛け。`lb_params = None` の値束縛(`let b: Int64 = 0` / `let empty[A]: List[A] = ...`)も同経路 |
| `Match` | パターンは期待型に対する検査(MiniLang:1546-1570 の形に全面書き換え)。パターン変数は単相。ガードは束縛後の環境で Boolean。網羅性は遅延キューへ |
| レコード演算 + `RecordUpdate` | 既存実装(elab.ml:369-388)のバグ 0.2-2,3 を修正して流用。`RecordUpdate` は「制限してから拡張」と同じ型付け |
| `Variant` | `TVariant (TRowExtend (label, payload_ty, 新行変数))` |
| `Construct` | 宣言表から `dd_params` を各カインドの新変数に、フィールド型に `subst_params`。**式では全フィールド必須**(欠落エラー)。ラベル指定の並べ替え結果は `resolved` に書く(interp が再実装しないため) |
| `BinOp` | prims.ml の表引き(D9)。`&&`/`||` は両辺 Boolean、メソッド系は `unify fn_ty (TArrow([l; r] の行, ret, eff))`、`!=` は ret を Boolean に |
| `Perform` | D22 の規則で操作を解決し(結果の完全名 oid を `resolved` へ)、引数を単一化し、`unify eff (TRowExtend (エフェクト名ラベル, ラベル引数, 新行変数))`。行のラベルは**エフェクト名**であって操作名ではない |
| `Handle` | 節を分類(操作 / `return` / `cancel`。頭の PCtor 名で判別し結果を `resolved` へ)。対象エフェクトは D22(全節が属し全操作を網羅する候補が一意)。本体を `TRowExtend(label, param, eff)` で推論。操作節: `resume_ty = Some (TArrow(op_ret の1引数行, result, eff))` を注入し本体を eff で推論(MiniLang:1499 と同型)。**`return` 節・`cancel` 節は外側の eff で推論**(`retc`/`exnc` は自分のハンドラが外れた文脈で走ることを実測済み — 内側の行で型付けると型と実行が食い違う)。cancel は Unit と単一化。`return` 省略時は `unify body_ty result` |
| `Resume` | `env.resume_ty` が Some のときだけ許可(None なら「resume は操作節の中でのみ使えます」)。引数省略は op_ret が Unit のとき `()` を補う。D19 の構文検査(節本体の Lambda 内の Resume をエラー)もここで走らせる |
| `Run` | (1) スコープに入る前に結果変数(level)、(2) level+1 で `Rigid` を作り `h` を types に束縛、(3) 本体を `TRowExtend(Heap, h, eff)` で推論して unify。MiniLang:1530-1538 の3行 + 名前束縛のみの差 |
| `Hole` | 新変数(1行)。評価で実行時エラー |
| `Seq`(ブロック) | 各文を eff で。末尾式が値、なければ Unit |

型式の追加規則:

- **`EUnion`**: 各要素を elaborate して行に落とし、`row_append` で連結。末尾が行カインドの型変数
  (`#Even | #Odd | R` の `R`)ならそれを尾部に。**エイリアス(`IoError | ParseError`)は展開して行を splice**
  (EffectRow の splice と同じ機構をヴァリアント行に一般化する)。両辺とも閉じていれば結果も閉じる —
  これが `report`(sample.kel:157-162)の網羅性(`case _` 不要)の前提
- エイリアス展開: 透過(展開時に毎回 elaborate)、**部分適用禁止・非再帰は全エイリアス共通**(§2.1)

### 7.4 型クラス(D3, D11)

- 表(decls.ml): `class_decls`(パラメータカインド、メソッド名 → 型スキーマ、derive_structural フラグ)、
  `instances`((クラス, 型構成子名) → メソッド本体)。**インスタンス探索は表引き1回**
  (`Functor[List[_]]` は「頭が List、適用個数はカインドが決める」ので頭の名前だけがキー。MiniLang:274-277。
  頭の `_` 穴はカインド検査にのみ使う)
- コヒーレンス: `add_instance` で重複キーを拒否。それだけ(sample.kel:276)。
  **プレリュードと重複する宣言をユーザファイルが書いたときもこの規則で素直にエラーにする**
  (sample.kel 全体回帰は専用の薄いスタブで走らせるので衝突しない。§9.2)
- `add_class`(MiniLang:662-696 の直訳 + Keleut 差分):
  変数 → vcls に合併(+ 台帳登録)。Rigid → 宣言に無い制約はエラー(`[A: C]` と書け、と案内。
  **予約述語が Rigid に乗ったときは専用メッセージ**「型パラメータに整数リテラルは使えません。
  `0i32` のように接尾辞を付けるか具体型を使ってください」— `[A: Integral]` とは書けないため)。
  `TCon` → インスタンス表引き + 前提伝播(前提つきインスタンスは組み込み表のみ。`Show[List[_]]` 等)。
  閉じた行の `TRecord`/`TVariant` + derive structural クラス(Eq) → フィールドへ再帰(sample.kel:305-309)。
  `TApp`(頭が変数) → エラー(修飾型を持たない設計の正直な代償。MiniLang:689-695)
- クラスメソッドは「ただの多相定数」として値環境に登録(非修飾名 `add` と修飾名 `Add.add` の両方)。
  メソッド型は **クラスパラメータ(vcls 付き Generic)+ メソッド固有の型パラメータ
  (`val map[A, B, E]: ...`、sample.kel:318)の両方**を Generic 化して作る
- インスタンスメソッド本体は「クラス宣言のメソッド型に頭型を代入した型」への検査として推論。メソッドの網羅も検査
- **v0 制約: クラスパラメータが少なくとも1つの引数位置に現れないメソッドは宣言エラー**
  (実行時ディスパッチ(D3)の前提。`pure : (A) => F[A]` 型は不可)。
  sample.kel:329-333 が Monad/Applicative をプレリュードに置かないと明言しているので仕様と衝突しない

### 7.5 網羅性検査(`lib/exhaust.ml`)

- MiniLang §12(:1594-1790)を移植。ctor は `CVariant of oid | CData of oid | CLit | CRecord of oid list`
- **移植上の唯一の罠**: `CRecord` のラベルは重複する(タプル = `_item` の連なり)。
  MiniLang:1645 の `fs.toMap` は3要素タプルを1要素に潰すので**そのまま使えない**。
  型の行のフィールド順序に沿い、パターン側の同名フィールドを最左から順に割り当てる
  `align_record_pat`(ラベルごとのキュー)を書く
- `CData` の arity は多値。**ラベル指定パターンの欠落フィールドは `PWildcard` で補ってから行列に載せる**(§2.1 §6)
- `complete_sig`: 閉じたヴァリアント行 / 宣言表の全 ctor(`Never` は `Some []` — 節ゼロで網羅)/
  Boolean / レコード / それ以外は None(整数は反例構成)
- `close_variant_rows`(MiniLang:1699-1710)をそのまま移植
- ガード付き節は行列から除外(「必ずマッチ」と数えない。sample.kel:247-249)
- **検査は各 let 束縛群の generalize 直前に drain**(§7.2)。網羅性(missing)と**到達不能節(useful)の両方**を警告
- 重大度は警告。`--strict-exhaustive` でエラー化

### 7.6 エフェクト行まわりの補足

- `@ Print` = `@ {Print}` の略記。`@ {}` = `TRowEmpty`(純粋)。**`@` 省略 = 新しい行変数**(sample.kel:315-316)。
  `@ E`(行変数)と `@ Print`(エフェクト名)は構文上同形 — 区別は elab がスコープで行う
- EffectRow エイリアス: `brace_ty` の `BLabel` 要素がエイリアスに解決されたら `row_append` で splice(sample.kel:446)
- トップレベルの初期 eff は**ランタイム提供エフェクトの閉じた行 `{Console, Async}`**。
  (`Async` を入れないと sample.kel:529 の `crunch` がトップレベルから呼べず、§2.1 §11 の
  「yield_ は型検査を通り実行時 no-op」と矛盾する。)`perform print` をトップレベルに書くと
  「エフェクト Print をここでは実行できません」になる(正しい)。定義点は `prims.ml` の1箇所

### 7.7 プリティプリンタ(`lib/show.ml`)

MiniLang:491-590 を踏襲: 複数の型を同じ命名で(`show2`)、Generic は `A,B,...`、
Unbound(値制限で一般化されなかった変数)は `_A`、Rigid は `ς1`、カインド別の名前プール、
制約前置(`[A: Add + Mul] ...`。**予約述語はエラー経路の表示から除外**)、

**追加義務**: 行の全フィールドが `_item` で閉じていれば `(A, B)` に再糖衣化(§14 TODO、約20行)。

### 8.2 値表現

```ocaml
type t =
  | VBool of bool | VInt32 of int32 | VInt64 of int64 | VFloat64 of float | VText of string
  | VRecord of (oid * t) list      (* Scoped Labels: 重複可・順序付き。先頭が最新。Unit = VRecord [] *)
  | VVariant of oid * t            (* ペイロードは常に単値 *)
  | VData of { d_type : oid; d_ctor : oid; d_fields : t array }   (* newtype 値。d_type はディスパッチ用 *)
  | VClosure of closure            (* 多引数。let rec バックパッチのため c_env は mutable *)
  | VPrim of prim
  | VResume of resume              (* Effect.Deep.continuation + r_used/r_alive の防御検査 *)
  | VRef of t ref | VArray of t array
```

- **Unit/タプルを専用コンストラクタにしない**(仕様の「同一物」をそのまま実装に写す。
  等価・パターン・印字がすべて自動で揃う。ここを崩すと全演算に分岐が波及する)
- ラベル・識別子・操作名・ctor 名はすべて `Type.intern` の oid(型側と同じインターン表)。
  操作名は elab が `resolved` に書いた完全名(`"Console.write"`)を使う
- レコード演算: `record_select`(最左)/ `record_extend`(cons)/ `record_restrict`(最左を1つ消す)/
  `record_take`(選択+制限。パターン照合用)/ `record_update`(最左をその場で差し替え)
- 構造的等価(`derive structural` の実体): レコードは「左のフィールドを順に、右から最左同名を取り出して消す」
  (異ラベル間の物理順序は違いうるので単純な順序比較は誤り)。**ヴァリアントはラベル一致 + ペイロード再帰、
  `VData` はタグ一致 + フィールド再帰**。フィールドの比較は `dispatch Eq.eq` 経由
  (フィールドにユーザ定義 Eq を持つ newtype があるとき宣言インスタンスを無視しないため)。
  Float は IEEE(NaN ≠ NaN)。関数の比較は実行時エラー
- 環境: `{ globals : 可変 Hashtbl; locals : 不変 Map }` の二層。globals 共有でトップレベルの
  相互参照・前方参照が無料で通る。`let rec` はクロージャ生成 → 環境構築 → `c_env` バックパッチ

### 8.3 評価規則の要点

- **評価順序「左から右」を OCaml の未規定評価順に任せない**。`eval_list` は `let` で順序を固定。
  `RecordExtend (rest, label, value)` は **value が先、rest が後**(sample.kel:203。
  AST のフィールド順と逆なのでコメント必須)
- ブロック: `let` は文、末尾式が値、なければ `VRecord []`。let パターン不一致は内部エラー扱い(elab が保証)
- **末尾呼び出し規約**: `eval` の末尾位置(Apply のクロージャ本体、Match/Block の本体)を OCaml の
  末尾呼び出しに保つ。**`eval` の再帰を `try ... with` で包まない**(1枚で TCO が消える)。
  エラー装飾は driver の最外周1回だけ。この規約を interp.ml 冒頭にコメントで明記
- 数値リテラルは**唯一 elab の型を読む場所**: ノードの解決型(defaulting 済み)の頭構成子名で
  `VInt32`/`VInt64`/`VFloat64` を作る。elab が `head_tycon_name : ty -> string option` を公開する

### 8.4 エフェクトハンドラ(D2。spike S2 で実証済み)

Keleut と `Effect.Deep` の対応(**全項目を実機で確認済み**。`260829-1-spike/effect/`):

| Keleut(sample.kel §9) | OCaml 5 `Effect.Deep` | 実証 |
|---|---|---|
| resume はアフィン | ワンショット継続(2度目は `Continuation_already_resumed`) | ✓ |
| resume は second-class | D19 の2段構え + `r_alive` | ✓ |
| resume の返り値 = handle 式全体の型(:363) | `continue k v : 'b` = `match_with` の結果型 | ✓(capture がそのまま動く) |
| `case return(x)`(省略時恒等) | `retc`(**親スタック上で走る** → return 節は外側の eff で型付け、§7.3) | ✓ |
| 深いハンドラ | `Effect.Deep` の意味論そのもの | ✓ |
| **最内**のハンドラが捕まえる | fiber の入れ子。`effc` が `None` を返せば外へ | ✓ |
| resume 未呼び出し → 自動巻き戻し(LIFO) | `discontinue` + `exnc`(下記) | ✓(with_file 2枚重ねで LIFO を確認) |

実装プロトコル(spike で確定した形。**素朴に書くと壊れる点が2つある**):

```ocaml
type _ Effect.t += Op : oid * t -> t Effect.t    (* 完全操作名 oid * 引数レコード(D5 に揃える) *)
exception Unwind of oid * t                       (* ハンドラ活性化 id * 保留中の節の値 *)
```

- `perform op(args)` → `Effect.perform (Op (op_oid, args_record))`
- `handle` → `match_with` 1枚。**`inst` は Handle ノードの評価のたびに `new_oid ()` で採番する**
  (AST ノード id を流用すると、同じ handle 式が入れ子に活性化したとき(再帰の中の handle、
  `with_file` の2回呼び)内側が外側宛の `Unwind` を自分宛と誤認して飲み込む — 誤動作を実測済み)
- `effc` で自分の操作なら節を評価。節の完了は3径路すべてを扱う:

```ocaml
Some (fun k ->
  let r = { r_k = k; r_used = false; r_alive = true } in
  match eval_clause env clause r with
  | v            -> r.r_alive <- false;
                    if r.r_used then v else Effect.Deep.discontinue k (Unwind (inst, v))
  | exception e  -> r.r_alive <- false;
                    if r.r_used then raise e
                    else Effect.Deep.discontinue k e)   (* ← 例外脱出時も必ず discontinue *)
```

  **節が例外で脱出したとき(`???` 到達、実行時エラー、外側の `Unwind` の通過)に `discontinue k e` を
  しないと、(a) 捨てた継続の中のハンドラの cancel が走らず資源が漏れ、(b) `effc` からの素の raise は
  親スタック上で伝播するため自分の `exnc` を素通りして自分の cancel も走らない** — 両方を実測済み
- `exnc`: 自分宛の `Unwind (id, v)`(id = inst)なら v を返す。それ以外の例外は cancel 節を
  実行してから再送出。cancel 節内の例外は抑制してログ(sample.kel:392)
- cancel 節の実行文脈: **外側のハンドラに加えて「いま巻き戻しを起こしている当のハンドラ」も有効**
  (deep handler は discontinue でも再設置される)。cancel 節からそのハンドラの操作を perform すると
  再入が起き、生成される `Unwind` は cancel 節内の例外として抑制される(実測済み。型検査を通る正当な
  プログラムで起きるので §12 に記録)
- `run` / `pinned` / `Heap` / `Blocking`: **操作を持たないエフェクトラベルは型レベル専用で実行時 no-op**
  という統一規則。`run h { e }` は `eval e`。Ref は素の OCaml `ref`
- 最外周に `with_runtime`(Console.write → 出力シンク、Async.yield_/sleep → 即 continue)を1枚敷く。
  漏れた操作は `Effect.Unhandled (Op ...)` を driver が捕まえて操作名込みで報告
  (既定の printer は中身を出さないので `Printexc.register_printer` が必要。実測済み)
- **性能特性(実測)**: 節の後処理が `continue` を effc の末尾式にしない実装は、perform 1M 回で約26倍・
  10M 回で約300倍の時間劣化(Stack_overflow はしない — fiber のスタックは伸びる)。
  `case op(x) => resume(...)` はプレリュードのハンドラのほぼ全部なので、
  **「節本体が構文的に `Resume e` のとき `continue` を末尾発行する」最適化を M8 に含める**
  (M10 送りにしない)。ゴールデンに 10万回 println の回帰テストを1本置く

### 8.5 型クラスの実行時ディスパッチ(D3)

- `tycon_of_value`: VInt32→Int32, VText→String, VData→d_type, ...。VRecord/VVariant → None(構造的)
- `dispatch cls meth args`: 引数を左から走査し、最初に「そのクラスのインスタンスを持つ」値で決定 →
  `g_instances[(cls, tycon)]` のメソッドを apply。見つからず derive structural なら構造的導出
  (v0 は Eq のみ)へ。コヒーレンスにより elab の判定と必ず一致
- クラスメソッドの識別子参照(`eq(a, b)` 等)は、クラス宣言処理時に「dispatch へのラッパ prim」を
  globals に登録することで素通しにする
- `BinOp` は prims.ml の表で dispatch(`&&`/`||` は短絡、`!=` は否定)
- 将来の静的化: elab が解決済みの呼び出し地点で `resolved` にインスタンスを注記 → interp は
  あれば表引きを飛ばす。**動的ディスパッチをフォールバックに残したまま段階的に移行できる**。
  v1 の HKT で `pure` 型メソッドが必要になったら発動

### 8.6 プリミティブとプレリュード

- プリミティブの**実装**は builtin.ml の表(名前 → OCaml 関数)、**型**は `lib/prelude.kel` 内の

  **ドット名の定義は含まない**(module elab は M10 のため。Ref/Array/Heap/Blocking は組み込み登録、§11.2)

### 11.2 Ref/Array の v0 シグネチャ(§14 TODO への暫定回答)

以下は**シグネチャの記法であり prelude.kel のソースではない**(effect 宣言にパラメータ構文が無いため
`effect Heap[h] = {}` はパースできない)。`Heap`(と `Blocking`)は操作なしの組み込みラベル、
`Ref`/`Array` は ctor なし newtype、各操作は組み込み値として **decls.ml / builtin.ml が直接登録する**:

```
Heap[h]                                  // 操作なしの組み込みエフェクトラベル
newtype Ref[h, A]    newtype Array[A]    // Array 自体は h を持たない(下記)
Ref.new  : [h, A] (A) => Ref[h, A] @ Heap[h]
Ref.get  : [h, A] (Ref[h, A]) => A @ Heap[h]
Ref.set  : [h, A] (Ref[h, A], A) => Unit @ Heap[h]
Array.new    : [h, A] (Int32, A) => Array[A] @ Heap[h]
Array.length : [A] (Array[A]) => Int32
Array.get    : [h, A] (Array[A], Int32) => A @ Heap[h]
Array.set    : [h, A] (Array[A], Int32, A) => Unit @ Heap[h]
Array.each   : [A, E] (Array[A], (A) => Unit @ E) => Unit @ E
```

sample.kel:464-468 の `sum` は `Array[Int32]` を run の**外**から受け取るので、`Array` はヒープパラメータを
型に持たず、読み書きだけが `Heap[h]` を要求する形にする(`h` は使用位置で決まる)。これで
`sum : (Array[Int32]) => Int32 @ {}` がそのまま型付く。
`Array.new`/`Ref.new` の `h` が結果型や効果行にしか現れないのは意図的(制約なし変数なので曖昧性検査の対象外)。

**既知の穴(仕様側に由来。§12 にも記録)**: `Array` が `h` を持たないため、
`let bump(a: Array[Int32]): Unit = run h { Array.set(a, 0, 1) }` は脱出検査を通り、
**引数を破壊する関数が純粋として型付く**。sample.kel:469 が `sum : ... @ {}` を要求している以上
仕様が要求している不健全性であり、v0 はこのまま実装する。
**親リポジトリへのフィードバック事項**: `Array[h, A]` にするか、読み取り専用 `Array` と
可変 `MutArray[h, A]` に分けるかを sample.kel §14 の TODO に追加すべき。

## 12. 意図した挙動として明記しておく裁定

- `fn(n) => n + 1` は `(Int32) => Int32` になる(`Add` 多相にはならない)。
  `+` の `Add` 制約とリテラルの `Integral` 述語が同じ変数に乗り、一般化点で既定化されるため。
  多相にしたければ `[A: Add]` を書く — sample.kel:245,253,293 の全用例と整合する言語設計として採用
- レコードパターンは開いた行(`{x = x}` で部分取り出し可)。タプルパターンは閉じる(arity 検査)
- 単一フィールドのレコード式/パターンは `{x = x}` と書く(`{x}` はブロック。sample.kel:26)
- `{base with ...}` の base は小文字識別子1個(§5.3 の2トークン先読みの帰結)
- 後置 `match`/`handle` は最弱: `x match {...} + 1` は書けない(括弧が要る。Scala と同じ)
- 型位置の `(A)` はグループ化ではなく 1-タプル `{_item: A}`。入れ子矢印の外側に `@` を書くには括弧が要る
- **サブエフェクティングは無い**: `@ {}` と注釈された関数はエフェクトのある文脈から呼べない
  (Apply が行を eff と単一化するため。MiniLang:2501-2506 と同じ)。v0 は「`@` 省略 = 行変数」なので
  実害が出にくいが、**v1 で `pub` の「`@` 省略 = `@ {}`」(sample.kel:568)を実装するときは、
  行の部分型付けを入れるか pub 署名を一般化された行変数として読むかの裁定が必要**(先送りすると設計変更になる)
- v0 の `pub` は可視性・注釈検査に影響しない(受理のみ)
- 網羅性・到達不能はどちらも警告(`--strict-exhaustive` でエラー)
- 整数オーバーフローは wrap-around、ゼロ除算は実行時エラー(仕様が決まったら変える)。
  v0 の実行時数値型は Int32/Int64/Float64 のみ(D13)
- **ハンドラが自分の節で継続を捨てたとき、そのハンドラの return 節も cancel 節も走らない**
  (spike で確認。資源を持つハンドラが自分で継続を捨てるなら後始末は節の中に書く。
  cancel を走らせる裁定にすると `try_` の正常な `#Err` 返却でも cancel が走ってしまうので現挙動が正しい)
- cancel 節の実行中は巻き戻しを起こしている当のハンドラも有効(再入した perform が起こす `Unwind` は
  「cancel 内の例外は抑制」規則に吸収される。§8.4)
- `Array` は run のリージョンから漏れる(§11.2 の既知の穴。`par` の決定性は v0 では型で保証されない)
- 未宣言名を使う sample.kel の検証は stubs.kel 前置で行う(§9.2)。sample.kel 本体は無改変

## 13. 本計画の効きどころ(まとめ)

1. **既存 Diktor の推論器は「MiniLang の前半」の骨格を持っている。** unify・レベル・oid インターン・
   level 引数渡しは拡張で済む(rewrite_row のフィールドレベル調整だけは要修正 — 0.2-11)。
   level 引数渡しと oid インターンは MiniLang より良いのでそのまま勝たせる。
2. **仕様の糖衣(タプル=行、Unit=空レコード、with=継続後付け、操作なしエフェクト=型専用)を
   実行時まで「同一物」として貫く**ことが実装量への最大のレバレッジ。専用表現を1つ入れるたびに
   等価・パターン・印字・行演算の全部に分岐が波及する。
3. **Keleut が resume をアフィン + second-class と決めたことが、OCaml 5 のワンショット継続と一致する。**
   エフェクトハンドラ(cancel の LIFO 込み)は spike 実測で約 120〜150 行に収まる見込みで、
   巻き戻し順序を管理するデータ構造は一切要らない。
4. **多引数クラスを持たないことで MiniLang の約250行(修飾型・制約ストア・ソルバ)が丸ごと落ち、
   型スキーマ用データ型すら不要になる。** 型クラスの実行は値タグディスパッチで elab と完全分離。
