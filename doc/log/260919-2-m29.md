### 台帳

計画 §1.0 の採番(V21〜V25)に従う。決着表は M33 の `260919-3-sync.md` にまとめる。

- **V17 / V20 解消**(72077f4)。値の型の位置のカインドを一般に検査する。V20 の観測点は valkind /
  annotkind と rowval3、V17 は rowval / rowval2 / hktval。
- **V18 解消**(ee0b96e、cd55e01)。newtype の本体を 1a の後で投機的に読む。
- **V19 解消**(77658e4)。台帳に無かった 2 形(`@ M.T`、`type W: EffectRow = MutableArray[…]`)も
  同じ枝で閉じた。
- **V21 新設**: リージョン変数 `h` を値の型の位置に書ける(regionkind2)。同じ根の裏側として、
  `@ Heap[Int32]` と `@ Heap[P]` が宣言の位置を通り、呼び出し点で内部名つきの診断になる。
  Region カインドを入れる日は両側を直す。
- **V22 新設、ただし主たる形は閉じた**(cd55e01)。計画が延期した形 — `newtype A[X] = MkA(B[{}], …)` を
  `B` より前に置く形 — は通る(specunit)。残るのは、投機が相手のパラメータのカインドを決められず、
  かつ前方参照の型引数が要素なしの波括弧のときである(specunit2。M29 前と同じ出力)。
  投機が届かないのは、相手の本体の 1 つのフィールドの中で、パラメータより先(右側)に
  ユーザ宣言のエフェクトラベルがある形である — effect の操作の登録は 1b なので、投機の時点では
  ラベルが未知で、そのフィールドの読みがそこで落ちる。ラベル付きの前方参照も同じ条件で
  落ちる(speclab)。どちらも宣言順を入れ替えれば通る(speclab2)。
- **V26 新設**: 行カインドが 1 つで、レコード行・ヴァリアント行・エフェクト行を区別しない。
  EffectRow エイリアスと行カインドのパラメータは、`{a: Int32 extends E}` の `extends` の右と
  ヴァリアントの和の末尾から値の型に入る。得られる型は直書きできるものに限られ、健全性は
  破れないが、「宣言は通るが値を作れない」形が残る。D131 は `extends` の右を位置に数えない
  (§11.4 の表)。旧バイナリも同じ。
- **V27 新設**: D82 の読み分けの抑制路(`~check_row:false`)では、読んだ結果のカインドが未確定の
  `KVar` のとき `same_kind` が Row に張るので、`Callback[F[E]]` は宣言が通り、使用点で
  「行型ではありません: _F[_A]」と内部名で落ちる。`@ F[E]` は D127 が落とす。旧バイナリも同じ。
- **V28 新設**: module の中の非修飾の EffectRow エイリアスは `@ WE[E]` だけが通り、`@ W` と
  `@ {WE[E]}` は「未知のエフェクト」で落ちる。旧バイナリも同じ。
- **V29 新設**: 型エイリアス経由で具体的な行を渡す形(`type Cb[E] = Callback[E]` に newtype の
  本体から `Cb[{Print}]`、EffectRow エイリアスへの `Wr[{}]`)は、宣言順によらず落ちる。
  エイリアスのカインド推論(D84)が 1b の後始末に走るので、1b の本番の読みが先に相手を
  Type に張る。型パラメータにカインドを注記する構文は無いので(D124)回避手段が無い。
  旧バイナリも同じ。
- **V30 新設**: newtype のフィールドが、自分より後ろで宣言された effect のラベルを参照すると
  「未知のエフェクト」で落ちる。`register_effect` が 1b の中で宣言順に走るためで、カインドとは
  別の軸の宣言順依存である。第11章の「宣言の順序に依存しません」はこの軸を含んでいない。
  旧バイナリも同じ。
- **V31 新設**: カインド注記の無い型エイリアスの本体が行でも、宣言は通る(`type P: EffectRow = {Print}`
  の後の `type Q = P`)。落ちるのは使用点で、`: Type` の注記と右辺のカインドは照合されない。
  逆向きの `type R: EffectRow = Int32` は宣言時に落ちる。旧バイナリも同じ。

### 敵対的検証(8 レンズ、指摘 39 件、確認 8 件)

レンズ: カインドの健全性 / 診断の位置と文言 / 投機の副作用 / 計画との整合と記録 /
エフェクト位置の全経路 / EffectRow エイリアスの非退行 / 仕様へ出す条文と実装の突き合わせ
(M32 の事前検査)/ 文芸化本文・cram の前書き・規約。各指摘を 1 名の反証者が独立に再現し、
31 件を反証した。エフェクト位置のレンズは 1 回目に結果を返せず、退行の修正後のバイナリで
やり直した(指摘 3 件、確認 0 件)。確認 8 件は根で数えると 5 件。

- **退行 1 件(high)** — `speculate_newtype` の `try` が本体全体を包んでいたので、フィールド 1 個が
  落ちると後続のフィールドが読まれなかった。effect の操作の登録は 1b なので、投機の時点では
  ユーザ宣言のエフェクトラベルがすべて未知で、`() => Unit @ {Log}` のような普通のフィールドが
  投機を打ち切る。パラメータが `KVar` のまま残ったところへ別の宣言の投機が `B[{}]` を型として
  読み、`same_kind` が相手を Type に張って、1b で `B` 自身が落ちた。

  ```
  effect Log = { log: (String) => Unit }
  newtype B[E] = MkB(() => Unit @ {Log}, () => Unit @ E)
  newtype A = MkA(B[{}])
  ```

  M29 前は exit 0、投入直後は「2:53 行カインドではない型パラメータです: E」。`B` を先に
  宣言した後方参照なので、計画が延期した V22(前方参照)の外にある。直し方は 2 つ(cd55e01)。
  例外をフィールドごとに握り潰す。投機の間(`speculating`)は、カインドが未確定のパラメータへ
  渡した要素なしの波括弧(`{}` と `{extends R}`)を読まずに飛ばす — この 2 形だけが型としても
  行としても読めるので、前者だけでは `MkB((() => Unit @ E, () => Unit @ {Log}))` のように
  1 つのフィールドの中で先にラベルへ当たる形が残る。1b がもう一度読むので、飛ばして失うものは
  無い。回帰は specfield / specfield2 / specinner / specinner2 / specfwd / specunit(ba0032c)。
  計画 J2.5 (6) が「設計変更になるので触らない」とした「張らない読み」を、曖昧な 2 形に限って
  入れた形になる。
- **本文の断定が偽 2 件**(上の退行と同じ根)。§11.31 の「ラベルを 1 つでも書けばどちらの順でも
  通ります」と、`kinds.t` の fwdrow の前書きの無条件の「宣言順に依存しない」。修正後も反例が
  残るので(speclab)、ラベルの有無が決めるのは「失敗した読みが張りを残すか」、投機が届くかは
  別の条件、と分けて書き直した(9bd13ae、0b1d91c)。タプルとレコードの要素は右から読む
  (`fold_right`)ので、「先にラベルへ当たる」とはラベルが右側にあることを指す。
- **§11.6 の全称が偽 3 件**(a7c9f5c)。「最後の枝へ通るのは 2 つだけ」 — 文法の `extends` は `eff` ではなく
  `ty` を取るので、`{… extends <ty>}` の右が第 3 の経路になる(effkind7)。「最後の枝に `TVar` は
  来ない、`KVar` は `F[E]` だけ」 — 1b の間は型エイリアスのカインドが未推論なので、エイリアスの
  適用経由で両方が届く(`newtype N[X] = MkN(() => Unit @ Id[X])`)。構造マッチを選ぶ根拠は
  「ここで `same_kind` を呼ぶと未確定のカインドを Row に張り、`@ F[E]` が通る」に言い換えた。
  「エフェクト位置で落ちる診断は 3 つ」 — `@` の右で落ちる文言は 5 つ以上ある。主語を「名前や
  適用形を書いて、読んだ結果が行にならなかった系統の言い分け」に狭め、Type エイリアスの診断に
  ゴールデンを置いた(effkind6。M6 以来 1 件も無かった)。
- **仕様へ出す文面 1 件**(M32 で直す)。J1.4 の「EffectRow のパラメータを持つ型は HKT のクラスの
  インスタンスになれない」は実装より広い。行のパラメータを前提の束縛子で埋めれば頭は
  Type を取って Type を返す形になり、`type instance[E] Sized[Cb2[_, _]]` は通る。禁止の主語は
  型ではなく頭のカインドである(§11.34 の本文は正しく書けている)。
