# コミット方針

このリポジトリでは作業の区切りごとに細かい粒度で積極的にコミットすること。

## ルール

- 明示的な「コミットして」という指示がなくても、以下のタイミングで能動的にコミットしてよい:
  - ひとつの論理的な変更が完了したとき（新機能・修正・リファクタ・ドキュメント更新など）
  - 動作確認が通ったとき
  - ユーザからの指示で一連の修正を終えたとき
- 粒度が細かすぎる方が望ましい。大きな変更は論理単位で複数コミットに分割する。
- コミットツリーは必要なら後から rebase / squash / reorder で整理されるので、途中状態のコミットがあっても構わない。
- 例外: 明らかに不完全・壊れた状態（コンパイルエラー、シンタックスエラー）でのコミットは避ける。
- `--no-verify` / `--no-gpg-sign` は使わない

## コミットメッセージ

- scope: 一行コメント\n\n本文
- scopeの種別は自由に決めたり追加して良い。
- コミットを追加しようとしているブランチ名が"ja/"で始まる場合はメッセージを日本語で書く。
  それ以外の場合は英語で書く。
  ただし既存のコミットは指示のない限り変えない。

## 破壊的操作

以下は従来どおり、ユーザの明示的な指示がない限り実行しない:
- `git push` (特に `--force`)
- `git reset --hard`
- `git rebase` / `git commit --amend` (共有済みコミットに対して)
- ブランチ削除

## 背景

ユーザの運用では「作った直後にコミット → 必要ならあとでまとめて整形」のワークフローを取っているため、
Claude 側から頻繁にコミットしても問題にならない。むしろコミットがないと戻りたい地点を失う。
